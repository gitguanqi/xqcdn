# XQCDN

A versioned front-end static asset library. Every library is organized as `library/version/file` and is safe for long-term caching. `libs/` is synced by scripts (primarily from the official npm registry; a few legacy versions come from an upstream CDN or are hand-maintained) — no more manual copying.

- Live site: <https://xqgj.cc/xqcdn/libs>
- Directory browsing: nginx + the [fancyindex](https://github.com/llorephie/ngx-fancyindex-theme-bootstrap) theme (`fancyindex/`)
- Static mirror: GitHub Pages (`dist/` build output, supports sub-directory hosting)

## Usage

```html
<!-- Versioned (recommended, permanently cacheable) -->
<script src="https://xqgj.cc/xqcdn/libs/jquery/3.6.0/jquery.min.js"></script>
<script src="https://xqgj.cc/xqcdn/libs/axios/0.19.2/axios.min.js"></script>
<link rel="stylesheet" href="https://xqgj.cc/xqcdn/libs/bootstrap/5.3.8/css/bootstrap.min.css">
<script src="https://xqgj.cc/xqcdn/libs/bootstrap/5.3.8/js/bootstrap.bundle.min.js"></script>
<link rel="stylesheet" href="https://xqgj.cc/xqcdn/libs/font-awesome/5.15.3/css/all.min.css">

<!-- Floating latest (legacy syntax, still works; nginx or the build output resolves it to the newest version) -->
<script src="https://xqgj.cc/xqcdn/libs/jquery/jquery.min.js"></script>
```

All three path forms are valid:

| Form | Example | Notes |
| --- | --- | --- |
| Versioned directory | `/libs/{library}/{version}/{file}` | The canonical path; content never changes, `Cache-Control: immutable` |
| Versioned directory + layout | `/libs/{library}/{version}/css/x.css`, `/js/x.js` | Some libraries keep the upstream `css/`, `js/` sub-directories |
| Flat latest | `/libs/{library}/{file}` | Always points to the newest version, short cache |

Machine-readable manifests:

| File | Purpose |
| --- | --- |
| `/libs/index.json` | Full manifest: versions, files, sizes, and sha256 for every library |
| `/libs/{library}/latest.json` | Pointer to the library's latest version |
| `/libs/{library}/README.md` | Reference examples for the library |
| `/libs/SHA256SUMS` | Full checksums |

## Source types

Every `library@version` entry in the manifest has an explicit `source` that decides whether it can be auto-synced (see [Maintenance](#maintenance) for the steps):

| `source` | Meaning | Examples |
| --- | --- | --- |
| `npm` | Fetch the tarball from registry.npmjs.org and verify `integrity` | bootstrap 5.3.8, vue 2.6.14, xqclip 0.0.3 |
| `url` | The version is not on npm; fetch via direct file links from the upstream CDN, pinning sha512 into the manifest on first fetch | jquery 1.10.0 (code.jquery.com) |
| `manual` | No verifiable upstream; registered only, never downloaded; `upstream: "none"` marks a third-party historical copy | opensans 0.0.1, xqvideo 0.0.1 |

> Only bootstrap 3.4.1 / 4.6.0 / 5.0.2 / 5.3.8 are kept; 2.3.2 has no verifiable upstream artifact and is missing the glyphicons images, so it was removed.

## Directory layout

```
libs/                 versioned static libraries (generated by scripts/sync.mjs, do not edit by hand)
libs.manifest.json    sync manifest: which directory maps to which npm package, version, and files
scripts/              sync / generate / validate / build scripts (zero dependencies, Node >= 18)
deploy/              nginx config: fancyindex-app.conf, nginx.conf.example, latest/*.conf
fancyindex/          nginx directory-listing theme (based on the upstream MIT theme, see fancyindex/LICENSE)
img/ fonts/           miscellaneous site images and fonts
soft/                self-used tools and nginx module archives (with SHA256SUMS)
404.html             self-contained error page (zero external dependencies)
```

## Maintenance

Prerequisites: Node.js >= 18, no `npm install` needed (the scripts have zero dependencies).

Library maintenance follows two routes, chosen by the `source` field in the manifest: **A. Auto-pull** (npm / url) or **B. Manual maintenance** (manual).

### A. Auto-pull (source = npm / url)

For libraries whose artifacts can be fetched directly from the official npm registry or an upstream CDN: most third-party libraries, plus self-owned libraries published to npm (the xq\* family).

**① Register a new version (manifest only, no download)**

```bash
node scripts/sync.mjs --add axios@1.7.9   # register a specific version
node scripts/sync.mjs --add vue           # omit the version to register the npm latest
```

After registering, you must add `files` rules: each `{"from": "path inside tarball", "to": "path under libs/"}` (for url sources write `{"url": "direct link", "to": "..."}`), then materialize it.

**② Materialize to disk**

```bash
node scripts/sync.mjs --apply                 # all npm/url sources
node scripts/sync.mjs --apply --only axios    # sync only one library (accepts "library" or "library@version")
node scripts/sync.mjs --apply --offline       # use only packages already cached in .cache/tarballs
node scripts/sync.mjs --apply --force         # overwrite entries that were hand-edited
```

`--apply` will: pull the tarball → verify integrity(sha512) → extract the dist build artifacts per the `files` rules → write to `libs/{library}/{version}/` → refresh fingerprints.

**③ Upgrade to the latest version**

```bash
node scripts/sync.mjs --upgrade                 # full health check (dry-run, writes nothing)
node scripts/sync.mjs --upgrade axios           # a single library: first verify the new version's file rules still match
node scripts/sync.mjs --upgrade axios --apply   # materialize + rewrite the manifest + auto-rebuild indexes
node scripts/sync.mjs --upgrade axios,vue --force   # bypass the PIN_NOTES major-version lock
```

- dry-run by default; it only downloads and validates file rules when a library is named.
- `PIN_NOTES` in `scripts/lib/sources.mjs` is a protection list (vue, jquery, echarts, codemirror…); its major version is not changed unless `--force`.
- Libraries not named that cross a major version (e.g. markdown-it 12 → 15) are skipped with a notice; naming one means you accept the jump.
- If a renamed file in the new version breaks the old rules: `--upgrade` reports the missing files before writing (the directory is never half-written); add the correct `"from"` to `files` and run again.
- When the target version is not on npm (e.g. legacy bootstrap 2.3.2): change that entry to `source: "url"` and give each rule a `url` (see jquery 1.10.0), or mark it `source: "manual"` + `upstream: "none"` with a note.

**④ Rebuild derived files**

```bash
node scripts/index.mjs    # generates index.json / per-library README / SHA256SUMS / deploy/latest/*.conf / THIRD-PARTY-NOTICES.md
```

**⑤ Check**

```bash
node scripts/sync.mjs --check     # disk matches recorded fingerprints (CI red line)
node scripts/sync.mjs --audit     # whether the manifest declarations have drifted from the upstream archive
node scripts/validate.mjs         # missing references / empty files / license coverage / version numbers / source declarations
```

### B. Manual maintenance (source = manual)

For libraries with no verifiable upstream: third-party historical copies (e.g. the Open Sans font, Apache-2.0), and self-owned libraries not published to npm (xqvideo, xqonline). These are never downloaded — only registered; you place the files under `libs/` yourself.

**① Place files by hand**

```
libs/{library}/{version}/
├── some.js
├── some.css
└── ...
```

e.g. `libs/opensans/0.0.1/css/opensans.css`, `libs/opensans/0.0.1/fonts/OpenSans-Bold.woff2`.

**② Register in the manifest**

Add an entry to the `packages` array in `libs.manifest.json` (or first run `node scripts/sync.mjs --add opensans@0.0.2 --source manual` to generate a skeleton, then fill in `files`):

```json
{
  "name": "opensans",
  "version": "0.0.1",
  "source": "manual",
  "files": [
    { "to": "css/opensans.css" },
    { "to": "fonts/OpenSans-Bold.woff2" }
  ]
}
```

Notes:

- `source: "manual"` without a `pkg`: means do not download, register only.
- In `files` write only `to` (the relative disk path) listing every file the version contains; unlike npm sources there is no need for `from`.
- For third-party libraries, also note the copyright and license in `THIRD-PARTY-NOTICES.md` (Open Sans's Apache-2.0 copyright is recorded there).

**③ Refresh fingerprints**

```bash
node scripts/sync.mjs --adopt
```

`--adopt` rebuilds the `.meta.json` fingerprints from the current disk state; for already-registered entries it only refreshes fingerprints and never changes `source`, so a manual entry is never silently switched to npm.

**④ Rebuild + check**

```bash
node scripts/index.mjs
node scripts/sync.mjs --check
node scripts/validate.mjs
```

**To update an existing manual version**: edit the files under `libs/{library}/{version}/` directly → re-run `--adopt` to refresh fingerprints → `--index` → `--check`. Do not hand-edit `.meta.json`.

### General script notes

- Tarballs are read only; no package scripts are executed and `postinstall` is never run.
- The download cache lives in `.cache/tarballs/`, unpacked only after `integrity` (sha512) verification; url sources reuse the same cache, so `--offline` works too.
- Before writing, an EOL-agnostic comparison (`sha256Loose`) is used; files that already match are not rewritten, avoiding meaningless diffs.
- Entries marked `source: "npm"` / `"url"` that were hand-edited are refused by `--apply` unless you pass `--force`.
- `--adopt` only refreshes fingerprints and will never silently convert a hand-maintained entry to npm.
- When an upstream build references absolute URLs such as `unpkg.com`, use the entry's `rewritePaths` to rewrite them back to this CDN (e.g. xqshare), so automation never changes live behavior.

## Deployment

### A. nginx (primary site)

Requires `ngx_http_fancyindex_module` and `ssi on`, and `deploy/latest/*.conf` must be included:

```nginx
server {
    root  /data/www;
    ssi   on;

    error_page 404 /404.html;
    location = /404.html { internal; }

    location /fancyindex/ { alias /data/www/fancyindex/; }

    # flat legacy URLs -> latest version directory
    include /etc/nginx/xqcdn/latest/*.conf;

    # mounted at the site root
    location /      { include /etc/nginx/xqcdn/fancyindex-app.conf; }

    # also mounted at a sub-directory
    location /cqcdn/ { alias /data/www/; include /etc/nginx/xqcdn/fancyindex-app.conf; }
}
```

A complete example (with both `Cache-Control` classes, dual mounting, and a standalone document root) is in `deploy/nginx.conf.example`.
The breadcrumb and home-link prefix is auto-derived by `fancyindex/js/main.js` from `#nginx-fancyindex-directory`, so neither `/libs/` nor `/cqcdn/libs/` needs any config change.

### B. GitHub Pages (static mirror)

GitHub Pages has no fancyindex / SSI / rewrite, so a build step substitutes for them:

```bash
node scripts/build.mjs --base /xqcdn/     # project site https://<user>.github.io/xqcdn/
node scripts/build.mjs --base /           # user site https://<user>.github.io/
```

The build: generates an `index.html` for every directory (reusing the same theme, with identical search and breadcrumb behavior), copies the flat latest URLs into real files, and writes `.nojekyll`.
Pushing to `main` auto-publishes via `.github/workflows/pages.yml`; `ci.yml` runs `sync --check`, checks that derived files are committed, `validate`, and a `build` smoke test.

## Script reference

| Command | Purpose |
| --- | --- |
| `node scripts/sync.mjs --adopt` | Rebuild the manifest from the current disk state (for migration / recovery) |
| `node scripts/sync.mjs --check` | Verify disk matches recorded fingerprints; the CI guardrail |
| `node scripts/sync.mjs --apply` | Download and materialize (npm / url sources; `--only` accepts `library` or `library@version`, plus `--offline`, `--force`) |
| `node scripts/sync.mjs --add pkg@version` | Register a new version |
| `node scripts/sync.mjs --upgrade [library]` | Upgrade to the latest version (dry-run by default, `--apply` to materialize) |
| `node scripts/sync.mjs --bump` | Alias of `--upgrade` (kept for backward compatibility) |
| `node scripts/sync.mjs --audit` | Check the manifest against the upstream archive for drift |
| `node scripts/index.mjs` | Generate `index.json`, per-library README, `SHA256SUMS`, `deploy/latest/*.conf`, `THIRD-PARTY-NOTICES.md`, `soft/SHA256SUMS` |
| `node scripts/validate.mjs` | Static checks: HTML/CSS references, empty files, sourceMappingURL, license coverage, version-number consistency, source-declaration validity |
| `node scripts/build.mjs` | Generate the GitHub Pages artifact (default `dist/`) |
| `node scripts/clean-duplicates.mjs` | Clean up files historically copied by hand into library root directories (dry-run by default) |
